# 14 — محرك العادة اليومية (السلسلة + المكافأة + الإشعار)

> هذا القسم يوثّق نظام "محرك العادة" المطبق في المرحلة 27: سلسلة الأيام المتتالية، ومكافأة أول دخول باليوم، والإشعار اليومي.

## 1. الفكرة (يعني ×3)
- **يعني (ببساطة):** موقعك يكافئ الطالب كل يوم يفتحه، ويذكّره إذا نسي.
- **يعني (مثال يومي):** مثل تطبيقات "عدّاد الأيام" — كل يوم متواصل يزيد الرقم، ويوم واحد انقطاع يرجعه صفر.
- **يعني (كيف يعمل فعلياً):** نتبع 3 طبقات: **عداد** (خوف الخسارة) + **مكافأة** (شهية الدخول) + **إشعار** (تذكير بالوقت). كل طبقة لها حماية ضد الغش.

## 2. الملفات
| الملف | الدور |

| `src/lib/streakCore.ts` | الدوال الصافية: `todayDateString()` و`dayBefore()` و`computeStreak()` |
| `src/lib/streak.ts` | منطق اليوم: `applyDailyStreak()` (الكتابة على قاعدة البيانات) و`claimDailyReward()` |
| `src/components/DailyHabitCard.tsx` | بطاقة 🔥 على الشاشة الرئيسية (العداد + زر المكافأة) |
| `src/views/HomeView.tsx` | يعرض `DailyHabitCard` بجانب بطاقتي "ساعات التركيز" و"الرتبة" |
| `server.ts` | `getAllPushSubscriptions()` + `sendDailyReminder()` + نقطة `/api/push/daily-reminder` + مجدول داخلي |
| `.github/workflows/daily-reminder.yml` | تشغيل آلي يومي (cron) يضرب نقطة التذكير كضمانة |
| `tests/streak.test.ts` | اختبارات حساب السلسلة (حدود الشهور، إعادة التصفير، إلخ) |

## 3. قواعد البيانات المستخدمة (لا ملف SQL جديد)
- حقل `streak` على مستندي `users/{uid}` و`profiles/{uid}`.
- حقل `lastActiveDate` (نفس التاريخ) — يُكتب فقط عند اكتشاف يوم جديد.
- حقل جديد `lastDailyReward` على `users/{uid}` — يحمل تاريخ آخر يوم صُرِف فيه للمكافأة.
- مستند `system/daily_reminder` (يُكتب من الخادم) — يحمل `lastSentDate` لمنع الإشعارات المتكررة.

## 4. منطق السلسلة
- `lastActiveDate === اليوم` ⇒ السلسلة كما هي (زيارة مكررة، لا كتابة).
- `lastActiveDate === أمس` ⇒ السلسلة + 1.
- `lastActiveDate < أمس` أو غير موجود ⇒ السلسلة = 1.
- التاريخ بصيغة UTC `YYYY-MM-DD` حفاظاً على الاتساق مع بقية الكود.

## 5. المكافأة اليومية
- متاحة فقط للمستخدمين المسجّلين (الزائر المجهول لا يحصل عليها).
- تُصرف عبر `requestXpGrant` → RPC `grant_xp` بقيمة +15 مع `p_force=true` — لذلك تخضع لحدود الحماية (≤120، ومهلة دقيقة) ولا يمكن تزويرها.
- بعد الصرف يُكتب `lastDailyReward = اليوم` فيختفي الزر حتى اليوم التالي.

## 6. الإشعار اليومي
- النص: "🚀 OrbitX — وقت الرحلة اليومية!" + "زملاؤك عم يبدؤوا جلسات تركيز. افتح الموقع ولا تخسر سلسلتك 🔥".
- الجدولة (مزدوجة ومنع التكرار عبر `system/daily_reminder.lastSentDate`):
  1. مجدول داخل الخادم: `setTimeout` بعد دقيقة من الإقلاع + `setInterval` كل 30 دقيقة، عند الساعة ≥ `DAILY_REMINDER_HOUR` (افتراضياً 15:00 UTC).
  2. وورك فلو GitHub يومياً الساعة 16:00 UTC يضرب `/api/push/daily-reminder`.
- الحماية: النقطة ترفض الطلب بدون السرّ (`DAILY_REMINDER_SECRET`) سواء في الـ header أو `?secret=`، مع حد 10 طلبات/ساعة.

## 7. خطوة الإعداد (مرة واحدة) للإشعار اليومي
1. في إعدادات تطبيق Render: أضف `DAILY_REMINDER_SECRET` = سرّ من اختيارك (مثلاً `Xy9k!abc`).
2. في GitHub: Settings → Secrets and variables → Actions → أضف `REMINDER_URL` = `https://<رابط-تطبيقك>/api/push/daily-reminder?secret=<نفس-السر>`.
3. شغّل الرفع الجديد مرة واحدة، ثم من تبويب Actions → Daily reminder push → Run workflow للتجربة اليدوية.

## 8. ملاحظات للحماية
- المكافأة تُصرف عبر دالة `grant_xp` المحروسة فقط — لا يُكتب الـ XP من العميل.
- الزائر المجهول معزول تماماً عن المكافآت.
- كتابة `streak/lastActiveDate` تتم فقط عند وجود يوم جديد لتقليل استهلاك الحصة.
