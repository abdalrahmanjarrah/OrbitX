## 1. وظيفة القسم — يعني ×3
- **يعني (ببساطة):** نظام فرق دراسة، حتى 10 أصدقاء تحت اسم واحد يجمعون نقاطهم مع بعض.
- **يعني (مثال يومي):** مثل "غرفة العائلة" في تطبيق مشترك — كل واحد لما يدرس بترتفع نقاط الغرفة كلها، وفيهم رئيس ونواب وغرفة نقاش خاصة.
- **يعني (كيف تعمل فعلياً):** مستند واحد في `fleets/{id}` يحتوي XP جماعياً، وكل منح XP من أي عضو يمر عبر RPC `grant_xp` على الخادم فيزيد `fleets/{id}.xp` تلقائياً. العمليات كلها من المتصفح مباشرة عبر واجهة Firestore المتوافقة في `supabaseAdapter.ts`.

## 3. تدفق البيانات

**إنشاء أسطول:**
```
المستخدم يكتب الاسم + الوصف
  → addDoc("fleets", {ownerId: أنت, members:[أنت], xp:0, ...})   (سطر 357)
  → updateDoc("users/أنت", {fleetId})                             (سطر 366)
```

**الانضمام المباشر:**
```
زر "انضم" على أسطول عام
  → updateDoc("fleets/{id}", {members: arrayUnion(أنت)})          (سطر 415)
  → updateDoc("users/أنت", {fleetId})                             (سطر 418)
```

**قبول دعوة:**
```
دعوة في users/أنت.fleetInvites
  → writeBatch: fleets/{id}.members+=أنت  +  users/أنت.fleetId=id وfleetInvites-=id   (سطر 229-241)
```

**المستمع الحي للأسطول النشط** (سطر 251-282):
- يسمع أي تغيير على `fleets/{fleetId}`.
- **أمان ذاتي:** لو اكتشف أنك لست في `members` (طُردت أو حُلّ الأسطول) → يحذف `fleetId` من ملفك تلقائياً حتى لو نسيت.

**دردشة الأسطول** (سطر 335-351):
- مستمع على `fleets/{id}/messages` آخر 50 رسالة `orderBy(timestamp, desc)` ثم يُعكس الترتيب.
- الإرسال `addDoc` إلى نفس المسار (سطر 438-452).

**XP جماعي:**
```
أي جلسة تركيز → requestXpGrant(uid, fleetId, ...)
  → grant_xp (Supabase RPC, SECURITY DEFINER)
  → users/{uid}.xp += xp  و  fleets/{fleetId}.xp += xp
```

## 6. مكونات الواجهة

**حالة "بلا أسطول"** (سطر 454+):
- بطاقة ترحيب "تحالف الفضاء" بجماليات كونية (radar sweep, glow pulse).
- **قائمة الأساطيل المتاحة** (مرتبة بـ XP، أول 20) + زر "انضم".
- **بطاقة إنشاء أسطول** (اسم + وصف).
- **الدعوات الواردة** (بطاقة وردية، قبول/رفض).

**حالة "عضو/مالك":**
- **رأس اللوحة**: اسم + وصف + XP + ساعات التركيز + عدد الأعضاء `n/10` + أزرار (تفكيك للمالك / مغادرة مع تأكيد).
- **غرفة تواصل**: دردشة بأكواد ألوان (رسائلك indigo على اليمين، الآخرين على اليسار) مع صور avatar وصورة DiceBear افتراضية.
- **لوحة الطاقم**: صورة + اسم + مستوى + XP + شارة (👑 مؤسس / نائب مسؤول) + أزرار إدارة (ترقية/سحب نيابة/طرد) — تظهر فقط للمالك.

## 7. الأمان والصلاحيات

### طبقة Supabase (النشطة فعلياً)
- الأساطيل تُعامل كـ"مجموعة تعاونية": **أي مستخدم مسجّل يستطيع تعديل أي أسطول** — لا تحقق في الخادم من أنك عضو أو مالك.
- قيد وحيد: `grant_xp` هو المصدر الوحيد للـ XP الفردي (RLS يمنع تعديل xp/level مباشرة فوق سطر 655 في supabaseSchema.sql)، لكنه **يسمح بتعديل fleets.xp**.

### طبقة Firestore (احتياطية، قواعد فقط — `firestore.rules:517-548`)
| العملية | القاعدة |
|---|---|
| قراءة fleets | أي مسجّل |
| قراءة/كتابة الدردشة | **الأعضاء فقط** |
| إنشاء | `ownerId == request.auth.uid` وأنت في members |
| تحديث | المالك = كل شيء • العضو = فقط xp/totalFocusHours مع **قيد +200 كحد أقصى** • إضافة/إزالة نفسك |
| حذف | المالك فقط |
| سعة | `members ≤ 10` و`coAdmins ≤ 5` |

## 8. نقاط القوة
- XP الجماعي تلقائي عبر `grant_xp` — لا رمز عميل يعدّل xp الأسطول مباشرة.
- الطرد الذاتي: لو خرجت من members تتحدث بياناتك وحدها دون نسيان.
- تقسيم جلب الأعضاء على دفعات 10 لتجاوز حد `in`.
- واجهة كاملة وجميلة (أكواد كونية، رسوم متحركة خفيفة GPU).

## 9. نقاط ضعف وملاحظات للتعديل ⚠️
1. **فجوة أمنية كبيرة (أهم نقطة):** في طبقة Supabase الفعلية، أي مستخدم يستطيع `updateDoc` على أي أسطول — تعديل `ownerId` أو `coAdmins` أو `members` أو طرد الآخرين. حماية Firestore القوية غير مفعّلة لأن الاتصال يمر عبر `supabaseAdapter.ts` (متوافق لكن RLS يسمح بتحديثات عامة). **حل مقترح:** إنشاء RPC آمن (`SECURITY DEFINER`) في Supabase لكل عملية (انضمام/طرد/ترقية/تفكيك) يتحقق من الرتبة قبل التنفيذ، أو رفع جدول RLS ليطابق firestore.rules.
2. **`handleDisbandFleet` لا ينظّف** `fleetId` عند الأعضاء الآخرين — يعتمد على "الطرد الذاتي" في مستمعهم (سطر 259-272) لكي يُنفّذ. إن كان مستمعهم غير مفعّل (خارج الصفحة) يبقى `fleetId` عالقاً إلى أن يفتح صفحة الأساطيل.
3. **لا يوجد قيد "أسطول واحد للشخص" على الخادم** — القيد فقط `user.fleetId` في الواجهة. شخص ماهر يستطيع ضمّ نفسه لعدة أساطيل عبر دفع `members` يدوياً.
4. **الدعوات عبر `UserModal` تُضاف مباشرة** إلى `fleetInvites` دون موافقة مالك الأسطول على من يُدعى — قد تُستخدم لإغراق مستخدم بالدعوات.
5. **الأخطاء كلها `catch(() => {})`** — أي فشل يمر بصمت، المستخدم لا يعلم أنه لم يُنفَّذ (مثلاً انضمام فشل بسبب حد 10 أعضاء: لا رسالة).
6. **كود التنظيف القديم** (حذف "رواد التميز" عند دخول حساب مطوّر) **حُذف** مؤخراً — لم يعد موجوداً.
